# Contributing to `aiporator/SHIPOS`

This repo is the source of truth for the Leader-OS Supabase schema, dashboard
view catalog, and Claude Code wiring. It contains **no application code**.

## Branching

- `main` is protected. All changes go through PRs.
- Branch names: `feat/<short-name>`, `fix/<short-name>`, `schema/<migration-name>`,
  `docs/<topic>`, or `claude/<auto-generated>` for Claude Code sessions.

## Schema changes — non-negotiable rules

1. **Apply via Supabase MCP `apply_migration`.** Never run raw SQL against the
   project. Migrations are auto-named and recorded in the project's migration
   history; mirror the name in `docs/CHANGELOG.md`.
2. **Run `get_advisors` after every DDL change.** Paste the output in the PR.
   The only accepted WARN is `upsert_incomplete_attempt` being callable by
   `anon` (documented). Anything else — investigate before merge.
3. **Views are `security_invoker = true`.** Postgres defaults to `DEFINER`,
   which Supabase flags as ERROR.
4. **Trigger functions revoke from `public, anon, authenticated`** and grant
   only `service_role`. They run via the trigger machinery, not REST.
5. **Functions set `search_path = ...`** explicitly.
6. **`email_lower` is the cross-platform dedup key.** Any code path that
   creates or links a user must use it. Bypassing it creates duplicates.
7. **FKs have backing indexes.** Add a composite if a hot dashboard query
   needs it.

## Pull request flow

1. Open a PR using the template. Fill out the schema-change checklist if
   relevant.
2. CI runs JSON validation, Markdown lint, link check, and project-ref drift
   check. All must pass.
3. CODEOWNERS auto-requests review. Schema/runbook changes require explicit
   approval.
4. Merge with **squash**. The PR title becomes the commit subject.

## Local working environment

This repo is designed to be opened with [Claude Code](https://claude.com/claude-code).
The Supabase MCP server is wired in `.mcp.json` (project ref
`srujvjjncrszhaaxepxf`). Skills are pinned in `skills-lock.json`.

For Edge Function deploys and Vault secrets, follow `docs/RUNBOOK.md`. Those
operations run from a developer machine with `supabase login` complete, not
from CI.

## Commit messages

Conventional commits, lowercase subject, present tense imperative:

```
docs(schema): document email_lower dedup invariant
schema: add composite index on sessions(user_id, created_at)
fix(ci): correct project-ref grep
chore(deps): bump actions/checkout to v4
```

## What does NOT belong here

- Front-end source (Next.js, React, etc.) — lives in the front-end repos
- Edge Function source — lives in the Edge Function bundle
- Production secrets — lives in Supabase Vault and Vercel env vars
- Any file referencing a service-role key, anon key, or third-party API key
